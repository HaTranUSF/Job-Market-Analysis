Federal Data Job Market & GenAI Audit Analysis

An automated ETL & GenAI pipeline that standardizes USAJOBS postings, cleanses salary and location fields, loads records into PostgreSQL, and tests experimental LLM risk extraction using the Gemini API.

👤 Author: Ha Tran
🛠️ Core Stack: Python, Gemini API, PostgreSQL (ex-Snowflake), Power BI
📊 Dataset Scale: 5,588 Raw API Postings
📁 View GitHub Repository

The Business Problem

The federal data job market spans thousands of postings across dozens of government agencies, but unstructured text descriptions make standard query analysis difficult. Job titles vary widely ("Data Analyst," "Program Analyst (Data)," "IT Specialist (Data Management)"), pay scales flip between annual ranges and hourly rates, and crucial compliance details—such as required security clearance levels, financial system access, and internal audit oversight—are buried inside free-text descriptions. Standard SQL cannot query paragraph descriptions to evaluate an agency's risk profile or security exposure.

What I Built

A modular ETL pipeline paired with an experimental LLM enrichment worker:

1. Extract & Transform

  • API Ingestion: Paginated through 12 data-related role searches on the USAJOBS API with exponential backoff handling, fetching 5,588 raw postings.
  • Data Cleaning: Normalized hourly pay rates to annual compensation, standardized state locations, and classified varied agency job titles into uniform career tracks.

2. Experimental GenAI Risk Extraction

🧪 Experimental Feature Note: Gemini API Integration

The GenAI enrichment step (genai_enrichment.py) is currently an experimental proof-of-concept. To manage development costs and respect free-tier API rate limits (15 RPM), the pipeline was tested on a pilot batch of 26 postings. The worker is designed for idempotent batch processing to scale across the full PostgreSQL database.

  • Structured LLM Parsing: Utilized the google-genai SDK and Pydantic schema validation to extract structured security clearance, financial access, and audit control flags from unstructured descriptions.
  • Zero-Hallucination Grounding: Implemented a string verification check (validate_response) that matches every extracted LLM quote against raw job text, setting flags to False if a quote fails exact verification.

3. Database & Load Layer

  • PostgreSQL Pipeline: Loaded clean records and LLM risk flags into PostgreSQL using transactional upserts and content-hashing (MD5) to prevent duplicate rows during updates.

Key Architectural Decisions

Database Migration (Snowflake → PostgreSQL): Snowflake was used during initial warehousing experimentation. To eliminate compute costs while preserving enterprise relational modeling, transactional upserts, and schema indexing, the pipeline was migrated to PostgreSQL.

Grounding AI Outputs: Standard regex keyword searches proved too noisy for unstructured job descriptions. Combining Gemini LLM parsing with programmatic exact-quote verification ensured all AI-extracted audit flags were 100% grounded in source job text before database loading.
