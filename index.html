The Business Problem

Turning thousands of inconsistent federal job postings into a dataset that can actually be analyzed.

Why the raw data is difficult to analyze

Federal data-related postings use inconsistent job titles, salary formats, employment types, and location fields. Important operational information is also buried inside long job descriptions.

For example, security clearance requirements, financial-system access, and audit responsibilities cannot reliably be identified from the job title alone.

Core questions

  • Which data roles are agencies hiring?
  • How is demand distributed geographically?
  • How does compensation vary by role?
  • Which postings contain compliance or risk signals?

What I Built

The project is organized into separate extraction, transformation, loading, enrichment, and testing modules.

1. Extract

Built a USAJOBS API extractor that searches across 12 data-related role categories and handles pagination, request timeouts, persistent sessions, and exponential backoff for transient API failures.

The reference dataset contains 5,588 raw postings.

2. Transform

Standardized job titles into consistent career tracks, parsed locations, normalized salary fields, and standardized employment types and other structured attributes.

3. Load

Loaded cleaned records into PostgreSQL using transactional updates and database constraints to support repeatable pipeline runs.

Description hashing helps identify duplicate content published under different posting IDs.

4. Analyze

Connected the structured PostgreSQL data to Power BI to analyze role demand, compensation, geography, employment type, and other market characteristics.

Experimental GenAI Risk Extraction

An experimental enrichment layer for extracting structured compliance and operational risk evidence from unstructured job descriptions.

🧪 Pilot Feature

The Gemini enrichment worker was tested on a 26-posting pilot batch to manage API rate limits and development costs. The worker is designed for idempotent batch processing and can be extended to additional postings.

Structured extraction

The genai_enrichment.py worker uses the Google GenAI SDK and Pydantic validation to extract structured risk attributes from free-text job descriptions.

Security Clearance Financial Access Audit Controls

Source verification

Extracted quote snippets are checked against the original job description using programmatic string validation. If the quote cannot be verified against the source text, the corresponding flag is reset.

This creates a grounded evidence layer rather than storing unsupported LLM claims.

PostgreSQL Data Layer

The database separates core job data, extracted skills, and GenAI-derived risk evidence.

job_skills

Primary posting records including job title, organization, salary, location, and description.

job_posting_skills

Junction table mapping job postings to extracted skill keywords.

job_risk_attributes

Stores structured risk flags, extracted systems, and source evidence generated by the Gemini worker.

vw_job_risk_evidence

Reporting view joining posting metadata with risk-extraction evidence for downstream analysis.
